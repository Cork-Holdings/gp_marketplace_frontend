## Design Context

### Users
SME staff managing orders, appointments and services, and customers requesting or tracking them. They need to finish practical tasks quickly, often on a phone.

### Brand Personality
Calm, precise, professional. Plain-language operational clarity.

### Aesthetic Direction
Preserve the existing Geepay marketplace header, footer, typography, components and cobalt/sky/navy tokens. Bring Stripe-style operational clarity to status, next actions and cost breakdowns without introducing a new brand or shell. The dense, raw-ID merchant screens are an anti-reference. Use restrained motion and target WCAG AA, including reduced-motion support.

### Implementation Defaults
Existing React 19, Vite, React Router, Tailwind/CSS, custom form state and components; Radix-flavored primitives are present. Preserve these rather than introducing another design stack.

### Design Principles
1. Ask only for information the platform cannot infer; supply identity, store context, currency and valid choices from existing data.
2. Show one clear primary action per task and reveal conditional fields only when needed.
3. Put the work and its current state first; use spacing and typography before decorative color.
4. Explain errors at the point of action and preserve input for recovery.
5. Keep feedback immediate and motion purposeful, subtle and removable by user preference.
